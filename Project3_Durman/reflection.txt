 I made a few adjustments to the original form for this assignment to make it more secure, authentic, and easy to use. The two most significant modifications were to use a proper form method (POST) rather than DELETE and to make the password box visible and correctly set to type="password." Changing the method allows the form to function as intended because browsers only accept GET and POST for actual form submission. Along with basic HTML5 validation features like required, maxlength, and min/max, I also added the required input types like password, number, and email. It was necessary to include these built-in rules, as it helps to prevent bad or incomplete data from reaching the server entirely.

Another change was to enforce the "10 words or less" restriction on the message box. To prevent misuse and/or abnormally long inputs, I used a simple JavaScript counter to confirm the word count and stop submission if the limit is exceeded. While client-side validation can enhance the user experience, I learned that backend validation and sanitizing is still required to actually secure the application in a real production environment.
